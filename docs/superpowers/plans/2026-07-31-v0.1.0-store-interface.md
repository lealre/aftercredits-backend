# v0.1.0 (1/4) — Store interface + neutral models Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> LOCAL ONLY — do NOT commit this plan or the spec (user instruction).

**Goal:** Make the persistence layer swappable — services depend on a storage-neutral `store.Store` interface + `internal/models` types instead of `*mongodb.DB`, with zero behavior change.

**Architecture:** Introduce `internal/models` (neutral domain types, no bson/sql tags) and `internal/store` (the `Store` interface + neutral sentinel errors). Entity-by-entity, change each `*mongodb.DB` method to accept/return `models.*` and translate its errors to `store` sentinels, updating every caller; the `*Db` bson structs stay as the mongo storage representation with `*Db ↔ models.*` mappers. Finally, define the `Store` interface and swap service/api signatures `*mongodb.DB → store.Store`. The existing testcontainers integration suite is the safety net; nothing about API behavior changes.

**Tech Stack:** Go 1.24 (net/http, testcontainers-go, testify). No new dependencies.

## Global Constraints
- Module `github.com/lealre/movies-backend`; Go directive stays `1.24.0` (no tooling bump).
- Public repo: NO co-author trailer, NO Notion/personal/Pi mentions in commits/code/PR.
- **Behavior-preserving refactor:** NO API/request/response/JSON/status-code changes; NO new features; NO test *behavior* changes (only type imports the compiler forces). The full suite `go test ./... -count=1` must stay green after EVERY task.
- Handlers never call `api.Db.*` directly (CONVENTIONS.md §1) — keep `grep -rnE "api\.Db\." internal/api/*.go` empty.
- Import DAG (no cycles): `models` imports nothing project-local; `store` imports `models`; `mongodb` imports `store` + `models`; `services`/`api` import `store` + `models` (NOT `mongodb`); `server` (wiring) is the only place that imports `mongodb` to construct it.
- Branch `v0.1.0-store-interface` off `main`; PR title `v0.1.0 (1/4) — Store interface + neutral models`. No deploy (no runtime change).

## The mechanical transform (used by every entity task)
For a mongo DB method `func (db *DB) X(ctx, ..., a AaDb) (BbDb, error)`:
1. Change its signature to `func (db *DB) X(ctx, ..., a models.Aa) (models.Bb, error)`.
2. At the top, map inbound `models.*` params → internal `*Db` (via a `toXDb` mapper) if the body needs the bson struct; at the bottom, map the `*Db` result → `models.*` (via a `xDbToModel` mapper) before returning.
3. Replace returned `ErrRecordNotFound`/`ErrDuplicatedRecord` with `store.ErrRecordNotFound`/`store.ErrDuplicatedRecord` (translate `mongo.ErrNoDocuments`/duplicate-key at the boundary).
4. Update EVERY caller of `X` (grep for `.X(`): consume the `models.*` result; change `errors.Is(err, mongodb.ErrRecordNotFound)` → `errors.Is(err, store.ErrRecordNotFound)`. Service mapper funcs that took `mongodb.XDb` now take `models.X`.
Mappers live in `internal/mongodb/<entity>_mapper.go` (new per entity), e.g. `func userDbToModel(u UserDb) models.User` and `func userModelToDb(u models.User) UserDb`.

**models rule:** `models.X` mirrors `mongodb.XDb`'s fields with ALL struct tags removed and nested `*Db` types replaced by their `models.*` equivalents. Maps like `SeasonsRatingsDb` become `models.SeasonsRatings`.

## Self-review notes
- **Spec coverage:** `internal/models` + `internal/store` (Task 1); neutral types + mongo maps to models (Tasks 2-6); services import store/models not mongodb + interface swap + `var _` assert + grep-empty acceptance (Task 7); sentinel errors in store (Task 1, applied 2-6); behavior-preserving via existing suite (every task). All covered.
- **No new tests:** intentional — this is a refactor; the spec mandates the existing suite as the gate and byte-identical responses. Each task's "verification" is the full suite staying green (flag to reviewers: this replaces per-task TDD because adding tests would change test behavior, which the spec forbids).
- **Ordering rationale:** users→titles→ratings→comments→groups so groups (which calls the others) is converted last, after its dependencies already return models. The interface swap (Task 7) is last because it needs all methods already in `models.*` signatures.
- **Type consistency:** mapper names `<entity>DbToModel`/`<entity>ModelToDb`; models sub-types mirror `*Db` names minus `Db`; sentinels `store.ErrRecordNotFound`/`store.ErrDuplicatedRecord` used uniformly.
- **Risk:** Task 6 (groups) and Task 3 (titles) are the largest diffs (map↔list; many nested sub-types). If a task's diff is too large for one reviewer pass, it may be split by method-group during execution — note in the ledger, don't silently truncate.
