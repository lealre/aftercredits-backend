## WS1 · Security & config

**1. JWT secret from env (security).** `internal/server/server.go:33-34` hardcodes
`secret := "my-secret"` (committed, used for every env).
- Read `JWT_SECRET` from env; **fail fast at startup if empty** (same pattern as
  `factory.NewFromEnv` requiring API keys). Plumb it through `NewServer` /
  `NewServerWithProvider` onto `API.Secret`.
- `env.example`: add `JWT_SECRET`.
- **Test harness:** `tests/setup_test.go` builds the server via
  `NewServerWithProvider`; it must set a `JWT_SECRET` for the test run (env or a
  test constant). Update accordingly so auth tests keep passing.
- **Deploy note:** `JWT_SECRET` must be added to local + Pi envs at deploy;
  changing the secret invalidates existing tokens (users re-login).

**2. Fix `MONGO_DB` vs `MONGODB_DB` mismatch.** `env.example:5` documents
`MONGO_DB`, but `internal/mongodb/mongo.go:84` reads `MONGODB_DB` with a silent
fallback default of `"brunan"`. Following the example literally uses the wrong DB.
- **Decision:** standardize the code on `MONGO_DB` (consistent with
  `MONGO_USER/HOST/PORT`); replace the `"brunan"` fallback with a **generic**
  default name (e.g. `aftercreditsdb`). Update `env.example` to `MONGO_DB`.
- ⚠️ **Pi deploy is coordinated and deferred:** changing the var the code reads
  can repoint the Pi at a different DB. The Pi's `aftercredits/.env` and
  `pi/.env` must be verified/aligned to set `MONGO_DB=<the real prod db name>`
  **at deploy time — only when the user explicitly says so.** Do NOT touch the
  Pi for this as part of building v0.0.11.

**3. Configurable pagination.** Defaults are hardcoded: `titles.go:38-42`
(size 20, cap 100), `titles_handlers.go:138-139` (search limit 5).
- Introduce config (env) for default page size, max page size, default search
  limit, with the current values as defaults; use them instead of literals.
- Update `env.example`.

## WS2 · Conventions (the "Fix" items)

> **Deferred (own PR):** the handler→service refactor (routing the 14+ direct
> `api.Db.X()` calls through the service layer) is NOT in v0.0.11 — it lands as a
> standalone PR/version at the user's discretion (larger diff, easier reviewed
> in isolation). `CONVENTIONS.md` below still documents the rule as the standard,
> noting current known violations are addressed in that follow-up.

**1. `titles` service `ErrorMap`.** Other services expose sentinel errors +
`ErrorMap` (`groups/ratings/comments/users utils.go`); `titles` has none, so
`titles_handlers.go:82` special-cases `ErrTitleNotFound` inline and uses ad-hoc
strings ("Title already added", "Invalid IMDb title URL").
- Add `internal/services/titles/utils.go` with sentinel errors + `ErrorMap`;
  handler translates via the map like the others.

**2. `CONVENTIONS.md`** documenting the rules, linked from README:
- No DB access from handlers — always a service method *(the standard; full
  compliance via the deferred refactor PR)*.
- API errors are service-level sentinels mapped via `ErrorMap`; handlers
  translate, they don't define error strings.
- Comment invariants: TV series → top-level `Comment` empty, `SeasonsComments`
  per season; movie → `Comment` set, `SeasonsComments` empty.

**3. (Optional) comment-invariant guard.** The invariant holds by construction
(`comments.go:66,133`) but isn't validated. Add a small defensive check in the
comments service/mapper that rejects a document violating it. Low urgency.
