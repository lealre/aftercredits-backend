**Repo:** `github.com/lealre/movies-backend` at `/home/lealre/Github/aftercredits-backend`. goose/sqlc conventions reference: private `lealre/chirps-go`.
**Umbrella:** this is sub-project 2 of 4 in the Mongo→Postgres migration (v0.1.0). Sub-project 1 (the `store.Store` interface + `internal/models`) is MERGED to main. This builds the Postgres implementation of that interface; it is NOT wired into the running app (cutover = sub-project 4).

## Goal
A `postgres.Store` that implements the existing `store.Store` interface (42 methods, `internal/store/store.go`) against Postgres, with a goose-migrated relational schema and sqlc-generated queries, behaviorally equivalent to the Mongo store. Built + tested in isolation (testcontainers-postgres); the app keeps running on Mongo.

## Locked decisions (from brainstorming)
1. **TEXT primary keys** keeping existing string ids — users/groups/ratings/comments keep their Mongo hex ObjectId strings; titles keep their imdb `tt…` id. FKs are TEXT. (Makes sub-project 3's data copy straightforward.)
2. **Child tables** for the per-season sub-state (fully relational): `rating_seasons`, `comment_seasons`, `group_title_seasons`.
3. **pgx/v5** (`sqlc.yaml` `sql_package: pgx/v5`; `pgxpool` connection). Native `[]string` → `= ANY($1)` and native JSONB.
4. **Titles = hybrid**: query columns + a `metadata JSONB` that stores the complete `models.Title` object (source of truth for round-trip fidelity); the columns are denormalized query copies written from the same struct.
5. Mapping matches the Mongo mappers' **nil/empty-slice convention** so API responses stay byte-identical (carried forward from sub-project 1's final review).

## Non-goals
No wiring into `server`/`config` (app stays on Mongo); no data migration (sub-project 3); no deploy; no API/behavior change. The `store.Store` interface and `internal/models` are FIXED — do not change them.

## Schema (goose migrations, `sql/schema/NNN_*.sql`, `-- +goose Up/Down`)
Timestamps `TIMESTAMPTZ NOT NULL DEFAULT now()` unless nullable. TEXT ids.

- **users**: `id TEXT PK`, `name TEXT`, `email TEXT`, `username TEXT`, `password_hash TEXT`, `avatar_url TEXT NULL`, `role TEXT`, `is_active BOOLEAN`, `last_login_at TIMESTAMPTZ NULL`, `created_at`, `updated_at`. (`models.User.Groups` is NOT a column — assembled from `group_members`.) Unique on `username` and `email` where non-empty (partial unique indexes, mirroring the app's uniqueness).
- **titles**: `id TEXT PK`, `primary_title TEXT`, `type TEXT`, `start_year INT`, `rating_aggregate DOUBLE PRECISION`, `vote_count INT`, `added_at TIMESTAMPTZ NULL`, `updated_at TIMESTAMPTZ NULL`, `metadata JSONB NOT NULL`. `metadata` holds the full serialized `models.Title`; the columns are query copies. Index on `primary_title`, `type`, `rating_aggregate` for the sort/filter paths.
- **ratings**: `id TEXT PK`, `title_id TEXT NOT NULL`, `user_id TEXT NOT NULL`, `note REAL`, `created_at`, `updated_at`, `UNIQUE(user_id, title_id)`. **rating_seasons**: `rating_id TEXT REFERENCES ratings(id) ON DELETE CASCADE`, `season TEXT`, `rating REAL`, `added_at`, `updated_at`, `PRIMARY KEY(rating_id, season)`.
- **comments**: `id TEXT PK`, `title_id TEXT NOT NULL`, `user_id TEXT NOT NULL`, `comment TEXT NULL`, `created_at`, `updated_at`. **comment_seasons**: `comment_id TEXT REFERENCES comments(id) ON DELETE CASCADE`, `season TEXT`, `comment TEXT NOT NULL`, `added_at`, `updated_at`, `PRIMARY KEY(comment_id, season)`.
- **groups**: `id TEXT PK`, `name TEXT NOT NULL`, `description TEXT NOT NULL DEFAULT ''`, `owner_id TEXT NOT NULL`, `deleted BOOLEAN NOT NULL DEFAULT false`, `deleted_at TIMESTAMPTZ NULL`, `created_at`, `updated_at`. `CREATE UNIQUE INDEX ... ON groups(owner_id, name) WHERE NOT deleted` (the name-reuse-after-soft-delete rule).
- **group_members**: `group_id TEXT REFERENCES groups(id) ON DELETE CASCADE`, `user_id TEXT NOT NULL`, `PRIMARY KEY(group_id, user_id)`.
- **group_titles**: `group_id TEXT REFERENCES groups(id) ON DELETE CASCADE`, `title_id TEXT NOT NULL`, `title_type TEXT`, `watched BOOLEAN`, `watched_at TIMESTAMPTZ NULL`, `added_at`, `updated_at`, `PRIMARY KEY(group_id, title_id)`.
- **group_title_seasons**: `group_id TEXT`, `title_id TEXT`, `season TEXT`, `watched BOOLEAN`, `watched_at TIMESTAMPTZ NULL`, `added_at`, `updated_at`, `PRIMARY KEY(group_id, title_id, season)`, `FOREIGN KEY(group_id, title_id) REFERENCES group_titles(group_id, title_id) ON DELETE CASCADE`.

FK note: since sub-project 3 hasn't loaded data, cross-entity FKs like `ratings.title_id → titles.id` are OK to add now; but to keep the migration flexible (order of data load), the plan may keep ratings/comments `title_id`/`user_id` as plain TEXT (no hard FK) and only enforce the FKs that the app logic relies on (group_members/group_titles/seasons → their parents). Decide in the plan; default: hard FKs only within the group aggregate and the season children; ratings/comments reference titles/users by TEXT without a hard FK (matches Mongo's referential looseness and avoids load-order pain).

## Components
- **`sqlc.yaml`** (v2): `schema: sql/schema`, `queries: sql/queries`, `engine: postgresql`, `gen.go.out: internal/database`, `gen.go.package: database`, `sql_package: pgx/v5`. Configure `overrides`/`emit_json_tags` off (internal types).
- **`sql/queries/*.sql`** — one file per entity; sqlc `-- name: X :one|:many|:exec`, `$1` params, `RETURNING *` where useful. Batch reads use `= ANY($1::text[])`.
- **`internal/database`** — sqlc-generated (`db.go`, `models.go`, `*.sql.go`). Do NOT hand-edit.
- **`internal/postgres`** — `type Store struct { pool *pgxpool.Pool; q *database.Queries }`, `func New(pool *pgxpool.Pool) *Store`, `var _ store.Store = (*Store)(nil)`. Implements all 42 methods:
  - Thin methods → single sqlc call + row↔`models.*` map (mappers in `internal/postgres/mappers.go`, honoring the nil/empty convention; titles map via `json.Unmarshal(metadata)`).
  - **Aggregate reads assemble** from child rows, e.g. `GetGroupById` = membership-guarded group row + `group_members` (→ `[]string`) + `group_titles` + `group_title_seasons` (→ `map[string]GroupTitleItem` with `SeasonsWatched`). `GetRatingById`/`GetRatingsByTitleId(s)` join `rating_seasons`; comments join `comment_seasons`.
  - **Membership collapses to one join table.** In Mongo, membership is stored twice (`group.users[]` + `user.groups[]`); in Postgres it is the single `group_members(group_id, user_id)` row. So `AddUserToGroup`/`UpdateUserGroup` → insert that row; **both** `RemoveUserFromGroup(groupId, userId)` **and** `RemoveGroupFromUser(userId, groupId)` → delete that same row (idempotent). `models.User.Groups` and `models.Group.Users` are both derived from `group_members` (with `Groups` filtered to `NOT deleted` groups, so a soft-deleted group naturally drops out of every member's list — no per-member cleanup needed). `GetUsersFromGroup` joins `group_members → users`.
  - **Writes that touch children run in a pgx transaction** (`pool.Begin` + `q.WithTx(tx)`): e.g. `UpdateRating`/`AddRating` upsert the parent then replace `rating_seasons`; `UpdateGroupTitleWatchedForTVSeries` upserts `group_titles` + a `group_title_seasons` row and recomputes the top-level watched/watchedAt exactly as the Mongo version does; `SoftDeleteGroup` marks the group `deleted` (the groups service also loops `RemoveGroupFromUser` per member, which deletes the membership rows — consistent and harmless).
  - **`GetTitlesPage`** hand-written: build SQL in Go from a whitelist — filter `WHERE ($ids::text[] IS NULL OR id = ANY($ids))`; CASE 1 (orderBy ∈ {watched, watchedAt, addedAt} AND ids present) → `ORDER BY array_position($ids, id)` to preserve caller order; CASE 2 → `ORDER BY <mapped column> <ASC|DESC>` with the same remapping the Mongo store uses (`""`→`primary_title`, `imdbRating`→`rating_aggregate`, else the field). `LIMIT $size OFFSET $skip`; separate `COUNT(*)` for total. Column names come ONLY from a fixed whitelist map (no string interpolation of user input).
- **Superuser/CLI parity:** out of scope here — the `cmd/database` index/superuser tooling is Mongo-specific and gets its Postgres equivalent (goose run + a superuser insert) in sub-project 4. This sub-project only needs the migrations runnable by goose against a test container.

## Testing
- **testcontainers-postgres**: a test harness that starts a `postgres:16` container, runs the goose migrations (embed the `sql/schema` files or run goose programmatically), and exposes a `*postgres.Store`.
- Test the store methods directly (not through HTTP): round-trip each entity incl. the season child tables (a rating with seasonsRatings, a comment with seasonsComments, a group-title with seasonsWatched); group assembly (members + titles + seasons); soft-delete + name-reuse (the partial unique index); `GetTitlesPage` ordering (custom order-by-ids AND standard sort + pagination + count); the movie-vs-series comment invariant; unique constraint → `store.ErrDuplicatedRecord`; not-found → `store.ErrRecordNotFound`.
- Keep the existing Mongo integration suite untouched and green (this sub-project adds code, changes nothing wired).

## Acceptance criteria
- `sqlc generate` produces `internal/database` with no error; `internal/postgres` compiles; `var _ store.Store = (*postgres.Store)(nil)`.
- goose migrations apply cleanly up and down against a fresh Postgres.
- New postgres store tests pass against testcontainers-postgres; existing suite still green; `go build/vet`, `gofmt` clean; Go directive stays 1.24.0.
- `store.Store` interface and `internal/models` UNCHANGED (diff them = empty).
- No wiring change: `server`/`config`/`main` still build the Mongo store; the app runs on Mongo.
- New deps limited to `github.com/jackc/pgx/v5` (+ pgxpool), a goose library (`github.com/pressly/goose/v3`), and the testcontainers postgres module — none may bump the Go directive above 1.24.0.

## Open questions / risks
- Exact title column set vs JSONB: the plan freezes it by reading `models.Title`; source of truth = `metadata` JSONB, columns are query copies written from the same struct.
- sqlc + pgx/v5 array params: verify `= ANY($1::text[])` codegen; if a query is too dynamic for sqlc, hand-write it in `internal/postgres` (as `GetTitlesPage` already is).
- Season child-table writes must be transactional to preserve the Mongo "whole-doc replace" atomicity — enforced via `q.WithTx(tx)`.
