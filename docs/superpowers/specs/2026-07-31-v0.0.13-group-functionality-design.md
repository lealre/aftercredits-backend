## Goal
Make the stubbed group buttons work end-to-end: **rename**, **soft-delete** (owner), **leave** (non-owner). **Invite stays disabled.** Member management (view/remove members) is deferred. Deletion is a soft delete (mark as deleted, no data loss), gated in the UI by an S3-style type-the-group-name confirmation.

## Current state (verified 2026-07-31)
Backend group endpoints that exist: `POST /groups` (create), `GET /groups/{id}`, `GET /groups/{id}/users`, `POST /groups/{id}/users` (add user by userId), `GET /groups/{id}/titles`, `POST /groups/titles`, `PATCH /groups/{id}/titles` (watched), `DELETE /groups/{groupId}/titles/{titleId}`.
Missing: delete group, rename group, remove/leave user. `GroupDb` (`internal/mongodb/groups_db.go:18`) has no soft-delete field. DB has `UpdateGroup` (`groups_db.go:187`) already.
Group unique index: `ownerId_and_name_unique` on `(ownerId, name)` with a `partialFilterExpression` requiring both to be non-empty strings (`internal/mongodb/indexes.go:165-190`).

Frontend group UI (`src/pages/Groups.tsx`): Create (WIRED), Select-active (WIRED, localStorage only), Edit/Invite/Delete-Leave (STUBBED — "Coming soon" toasts, owner-gated). Service fns `updateGroup` (PATCH `/groups/{id}`), `deleteGroup` (DELETE `/groups/{id}`), `inviteToGroup` (POST `/groups/{id}/invite`) exist client-side but nothing calls them (`src/services/backendService.ts:777-840`). No leave/remove-user service fn. No type-to-confirm modal (`DeleteConfirmationModal.tsx` is movie-specific). ## Decisions (locked)
1. **Leave Group works** — non-owner removes self.
2. **Scope** = rename + soft-delete + leave. Member management (list/remove members) deferred. Invite disabled.
3. **Delete guard** = frontend type-the-name gate (client-side only, S3-style); backend `DELETE /groups/{id}` requires only owner auth (no name in request body).
4. **Name reuse after delete** = Option A: extend the unique index's partial filter to exclude soft-deleted groups, plus a migration setting `deleted:false` on existing active groups, so a deleted group's name can be reused.
5. **Leave path** = `DELETE /groups/{id}/users/{userId}`, self-only for non-owners.

## Backend design
All new endpoints, and all existing group reads, operate ONLY on non-deleted groups.

### Data model
- Add to `GroupDb` (`internal/mongodb/groups_db.go`): `Deleted bool \`json:"deleted" bson:"deleted"\`` and `DeletedAt *time.Time \`json:"deletedAt,omitempty" bson:"deletedAt,omitempty"\``.
- On `CreateGroup`, set `Deleted = false` explicitly (so new docs carry the field; needed for the partial index in Decision 4).
- **Exclude deleted from every group read filter** by adding `"deleted": bson.M{"$ne": true}` to the Mongo filter in: `GetGroupById`, `GroupExists`, `GroupContainsTitle`, `GetUsersFromGroup`, and the group-title listing lookup. (`$ne: true` matches docs where the field is false OR absent, so pre-existing groups without the field still read as active.)

### New endpoints
1. **`PATCH /groups/{id}` — rename.** Handler `UpdateGroup`. Owner-only (caller `currentUser.Id == group.OwnerId`, else 403). Body `{ "name": string }`; trim + reject empty (400). Reuses DB `UpdateGroup`. A duplicate `(ownerId, name)` hits the unique index → detect duplicate-key error → return the groups service's `ErrGroupNameTaken`-style sentinel mapped to 409 via `groups.ErrorMap`. Handler routes through the service layer (CONVENTIONS.md §1) — add `groups.RenameGroup(db, ctx, groupId, ownerId, newName)`.
2. **`DELETE /groups/{id}` — soft delete.** Handler `DeleteGroup`. Owner-only (else 403). Service `groups.SoftDeleteGroup(db, ctx, groupId, ownerId)`: set `deleted=true`, `deletedAt=now`, and remove the group id from EVERY member's `user.groups` array (all ids in `group.users`). Idempotent-ish: deleting an already-deleted/absent group → 404. Returns 200 with a simple message.
3. **`DELETE /groups/{id}/users/{userId}` — leave (self, non-owner).** Handler `RemoveUserFromGroup`. Rules for THIS version: the caller may only remove THEMSELVES (`userId == currentUser.Id`), and only if they are a NON-owner member. Owner attempting to leave → 403 (must delete). Removing a different user → 403 (member management deferred). Service `groups.LeaveGroup(db, ctx, groupId, userId)`: pull `userId` from `group.users` and pull `groupId` from that user's `user.groups`. Non-member → 404.

### DB methods to add (`internal/mongodb/groups_db.go` / `users_db.go`)
- `SoftDeleteGroup(ctx, groupId) error` — `$set {deleted:true, deletedAt:now}` on the group.
- `RemoveGroupFromUser(ctx, userId, groupId) error` — `$pull` groupId from the user's groups array (mirror of existing `UpdateUserGroup` which adds).
- `RemoveUserFromGroup(ctx, groupId, userId) error` — `$pull` userId from `group.users`.
- (Batch for delete: loop members calling `RemoveGroupFromUser`, or a single `$pull` across users with `{_id: {$in: memberIds}}`.)

### Index migration (Decision 4)
- Change `CreateGroupIndexes` partial filter to also require the group be active. `partialFilterExpression` supports `$eq` (not `$ne`), so use `{"deleted": {"$eq": false}}` added to the existing `$and`. This requires every active group to carry `deleted:false` → add a one-off dev migration (`cmd/dev-migrations/...`) setting `deleted:false` where the field is absent, run before/with the index reset. New groups already set `deleted:false` per Data model. The index must be dropped+recreated (reset) to pick up the new partial filter — fold into `CreateGroupIndexes` with the reset path, and note the migration ordering in the plan.

### Permissions summary
- Rename, soft-delete: owner only (403 otherwise).
- Leave: non-owner member removing self only (owner 403, other-user 403).
- All: 404 if the group doesn't exist or is already deleted.

## Frontend design
- **`ConfirmByTypingModal`** (new, reusable, shadcn `AlertDialog`): props `{ open, onOpenChange, title, description, confirmPhrase, confirmLabel, onConfirm, loading? }`. Confirm button disabled until the typed input `=== confirmPhrase` (exact match, trimmed). Used for owner delete with `confirmPhrase = group.name`.
- **Rename**: reuse the CreateGroupModal pattern (or a small `RenameGroupModal`) with a name input prefilled with current name → calls existing `updateGroup(groupId, { name })` → on success `refreshGroups()` + toast; on 409 show a "name already used" toast.
- **Delete (owner)**: open `ConfirmByTypingModal` (phrase = group name) → `deleteGroup(groupId)` → `refreshGroups()`; if `getGroupId() === deletedId`, clear it (`clearGroupId()`) or switch to another remaining group; toast.
- **Leave (non-owner)**: plain `ConfirmByTypingModal`-free confirm (simple AlertDialog, no typing) → new `leaveGroup(groupId, userId)` service fn (`DELETE /groups/{id}/users/{userId}`) → `refreshGroups()` + fix active-group pointer + toast.
- **Invite**: keep the button but make it explicitly, always disabled with a "Coming soon" tooltip; remove the "Coming soon" toast handler. Remove the static footer text claiming features are coming soon.
- Owner gating: Edit + Delete shown/enabled for owner; Leave shown/enabled for non-owner. (Groups.tsx already computes `isOwner`.)
- Wire via React Query mutations that call `refreshGroups()` (invalidates `['user']`/`['groups']`), consistent with `useGroups`.
- Add `leaveGroup` to `backendService.ts` mirroring the existing group fns' error handling; `updateGroup`/`deleteGroup` already exist and match the new routes.

## Edge cases
- Deleting/leaving the **active** group → clear or reassign `localStorage["group_id"]`; avoid leaving the app pointed at a gone group.
- Owner cannot leave (only delete). FE naturally shows Delete for owner / Leave for non-owner.
- Rename to a duplicate name → 409 → toast; no state change.
- Soft-deleted group's titles/ratings/comments remain in DB, unreachable via the filtered reads. No cascade.
- Pre-existing groups without the `deleted` field read as active (`$ne: true`); migration adds `deleted:false` so they're covered by the new partial unique index.

## Acceptance criteria
- Backend: new endpoints behave per Permissions; deleted groups excluded from all reads; member `user.groups` cleaned on delete/leave; `go build/vet`, `gofmt -l`, unit + integration suites green; zero `api.Db.` in handlers preserved; unique index rebuilt with the deleted-exclusion and a passing name-reuse-after-delete test.
- Frontend: rename, delete (type-to-confirm), and leave all work against the backend; invite disabled; active-group pointer handled on delete/leave; `npm run build` + lint at/under baseline; manual click-through clean.
